# Quality Standards

For application changes, run typecheck, relevant tests, production build, and review documentation. Never introduce secrets. Provide loading, empty, error, and demo states where applicable.

Use semantic HTML, keyboard-operable controls, visible focus, adequate contrast, and reduced-motion support. Keep domain rules separate from UI. Handle malformed or missing data explicitly; never turn unavailable evidence into a positive claim.

A passing build is not proof of product completeness or security.
